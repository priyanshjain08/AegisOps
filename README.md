# AegisOps

AI-assisted security incident detection, investigation and response for small teams.
Pipeline: **Detect → Correlate → Investigate → Recommend → Approve → Respond → Verify → Audit.**

> **Verification status (read first).** This repo was authored in a sandbox with no network, so
> PostgreSQL, Redis, Docker, `pip install` and `npm install` were unavailable.
> - **Executed and passing:** 41 unit/pipeline tests of the framework-free core in `backend/app/domain` (`cd backend && python -m unittest discover -s tests`).
> - **Written but NOT executed:** the FastAPI app, SQLAlchemy models, Alembic baseline, Celery worker, React frontend, Dockerfiles and Compose file. Expect to fix typos/integration issues on first run.
> - **Not implemented:** see *Known limitations*.

## Features
- Ingestion: JSON / JSONL / CSV upload, REST (`POST /api/ingestion/events`), per-record validation errors, UTC normalization, dedup by content hash, Celery path for large uploads.
- 8 configurable detection rules (brute force, suspicious login, privilege escalation, port scan, malware indicators, suspicious process, exfil volume, disabled controls). Heuristics, not confirmed attacks.
- Correlation by shared entities (IP / user / host) inside a window; time proximity alone never links alerts. Manual link/unlink.
- AI investigation: provider-independent (OpenAI-compatible / Anthropic), strict JSON validation (evidence IDs must exist, ATT&CK IDs allowlisted, actions allowlisted), versioned analyses, labeled non-LLM fallback.
- Response: allowlisted actions, human approval, idempotent execution, simulated firewall only.
- Assets, dashboard (DB-backed), audit log, PDF/CSV/JSON incident reports, simulated demo scenarios.
- RBAC (owner / security_admin / analyst / viewer) and org isolation on every query.

## Quick start (Docker, unverified)
```bash
cp .env.example .env   # set POSTGRES_PASSWORD, DATABASE_URL, JWT_SECRET
docker compose up --build
# UI http://localhost:5173  API docs http://localhost:8000/docs
```
Register an organization, open **Overview → Load simulated scenarios**, or upload `samples/sample_logs.jsonl` on **Events**.

## Local development
```bash
cd backend && pip install -r requirements.txt && alembic upgrade head && uvicorn app.main:app --reload
celery -A app.workers.celery_app.celery worker      # separate shell
cd frontend && npm install && npm run dev
```
## Tests
`cd backend && python -m unittest discover -s tests` (core, verified) · `pytest` also works.
`cd frontend && npm run typecheck && npm test` (no frontend tests written yet).

## AI provider
Set `AI_PROVIDER=openai|anthropic`, `AI_API_KEY`, `AI_MODEL` (and optionally `AI_BASE_URL`) in the backend env. Without them the UI shows a clearly labeled rule-based analysis. Keys never reach the browser.

## Known limitations
- No Socket.IO/WebSocket push: the UI polls every 10 s.
- Not implemented: global search endpoint, user/member management UI and endpoints, Integrations and Settings pages, notifications API, user profile editing, shadcn/ui, Playwright and frontend tests, DB-backed backend integration tests (pytest + Postgres), login-specific rate limits (only a global 300/min default).
- Alembic `0001` uses `create_all`; later migrations should be autogenerated and reviewed.
- Refresh token is kept in `sessionStorage` (XSS-exposed); consider httpOnly cookies for production.
- Suspicious-login rule has no geo data and makes no impossible-travel claims.
- Execution timeout for actions is not enforced beyond the simulated adapter being instantaneous.
